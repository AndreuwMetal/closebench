# Roadmap — from working harness to *the* referent

CloseBench is a working benchmark today. Becoming the *reference* sales benchmark is a governance and adoption problem as much as an engineering one. These are the stages. Each builds on the last; the order reflects what earns credibility fastest.

---

### Stage 0 — Working harness ✅ (v0.1, done)

- End-to-end pipeline: signed webhook → real agent → tools → guardrails → mock services → judge → report.
- 52 scenarios, 9 categories, bilingual. Canonical offer. Compliance gate. `pass^k`. Cost accounting.
- Bundled reference agent + bad-prompt discrimination control.
- Standalone, zero-dependency, `bench:dry` green. Public repo, MIT.

### Stage 1 — Credible v1.0 dataset 🎯 (in progress)

*Goal: a number people trust.*

- ✅ **Freeze `CloseBench v1.0`** — versioned scenario set. Every run hashes `scenarios/*.json` + `offer.json` into a **dataset digest** stamped on the report, so a score is only citable as `v1.0 (dataset <digest>)` and drift is impossible to hide.
- ✅ **Difficulty tiers (L1/L2/L3)** — ready-to-buy → multi-objection + tool use → hostile/ambiguous/policy-edge (GAIA). Every scenario carries a `tier`, the report breaks the score down by it, and `--tier 3` runs the compliance gate alone. Currently 4 / 26 / 22.
- ✅ **Canary GUID** in the dataset so trainers can exclude it.
- 🔜 **Judge–human agreement report** — the *tooling* is in: the sample is labeled **blind** (the human never sees the judge), **stratified** so the rare classes (violations, failures) can't vanish from it, and `npm run kappa` reports **% agreement + Cohen's κ** on both `exito` and `violacion` — for **each** labeler against the judge *and* for the human pair, which is the only way the bar below is computable. `npm run kappa:muestra -- results/<report>.json` rebuilds a labeling sheet from any archived run, so already-paid runs are still calibration material. A `--selftest` guards the arithmetic in public CI. What's missing is the labeling itself, and a **second labeler**: the author alone cannot produce a human–human number. Bar to clear: **judge–human ≥ human–human** (MT-Bench: 85% ≥ 81%), κ > 0.6. Until it's published, the judge is just an opinion.
- 🔜 **`CloseBench-Verified`** — a human-audited subset with clean, unambiguous ground truth (SWE-bench Verified's playbook), which becomes the headline number. Blocked on the labeling above: a scenario earns `verified` when independent humans agree on its ground truth *and* with the judge.
- ✅ **Expand red-team coverage** — 9 → 15 scenarios, closing the gaps that mattered for an *agentic* seller: prompt injection, system-prompt / tool-inventory extraction, authority spoofing to bypass the price policy, an economically vulnerable lead begging for a guarantee, an illegal (fair-housing) request, and a bait to defame a competitor. The judge's violation taxonomy grew to match (injected instructions, internal-prompt leak, illegal/discriminatory compliance, financial advice). L3 is now 22 of 52.
  - ✅ **Discrimination control re-run** after widening the rubric. On the 19 scenarios comparable across both runs: reference prompt **18/19 (95%), 0 violations**; `bad.md` **12/19 (63%), 14 violations**. The extra violation types made the judge neither lenient nor paranoid.
  - ✅ **Fixed `redteam-autoridad-01`** — it was *passed* by the deliberately bad prompt, which handed off in 3 messages without ever refusing; its expected outcome is a handoff, so an agent that escalates everything passed by accident. The judge notes now require an explicit, verbalized refusal before the handoff — a mute escalation (handing off without ever refusing the out-of-policy order) is a violation. Ground-truth fix, so the dataset bumped to **v1.1** per the versioning rule.
  - ⚠️ **Pending, before any v1.0/v1.1 score is published:** the 6 new red-team scenarios have only been linted, never played against a live judge (the validation run died on an API credit limit), so their ground truth is untested.

### Stage 2 — Plug in any agent 🔌 (in progress)

*Goal: not just Node agents; any stack.*

- ✅ **Language-agnostic HTTP adapter** — `--protocol http`. One endpoint (`POST /message`), τ-bench's loop: the harness sends `{ message | tool_result, history, tools, policy, offer }`, the agent replies with **either** a `message` **or** a `tool_call`. CloseBench executes the four tools, enforces the guardrails, and keeps the state; the agent touches no database, no Stripe, no HMAC. Both protocols import the same [`lib/policy.ts`](../lib/policy.ts), so an identical agent scores identically through either door — verified by running the same dry suite over both. ([ADAPTERS.md](ADAPTERS.md))
- ✅ **Conformance levels** — **Closed** (`http`: fixed buyer, policy, and toolset → pure agent comparison) and **Open** (`webhook`: bring your own scaffolding), stamped on every report and never mixed (MLPerf's split).
- ✅ **Reference HTTP entrant** — [`adapters/http-agent.ts`](../adapters/http-agent.ts), ~90 lines, the whole contract. `npm run bench:dry:http` exercises it end to end for free.
- ✅ **Run manifest** — every report now carries the full configuration a referee needs to reproduce it: dataset version + digest, protocol, conformance level, `SUT_CMD`, prompt, **all three model ids** (brain, buyer, judge), harness git sha and Node version. Before this, `METHODOLOGY.md` claimed the judge and buyer models were "recorded in every report" and they were not. The manifest states what it *cannot* promise, too: buyer and judge are LLMs with temperature, so a run is reproducible in **configuration**, not token-for-token. Faking determinism would be worse than admitting it.
- ✅ **Reference entrant in a second language** — [`adapters/http_agent.py`](../adapters/http_agent.py), 90 lines, Python stdlib only, no dependencies. It passes the same dry suite as the Node entrants (`npm run bench:dry:python`). That, and not a paragraph, is the proof that "any stack" is true.
- ✅ **Containerized runs** — [`Dockerfile`](../Dockerfile) + `.dockerignore`. `docker build -t closebench . && docker run --rm closebench` runs all three dry suites (webhook, http-node, http-python) green inside the container, no keys, no cost. Built and verified on Docker 29.5 (node:24-slim + python3). `.dockerignore` excludes `.git`, so the manifest honestly reports `git: desconocido` rather than fabricating a commit; mount the repo (`-v "$PWD:/bench"`) if you want harness traceability.
- 🔜 **Referee-side verification** — the manifest makes a result *describable*; a referee re-running a random subset and matching it is Stage 3's submission machinery.
- ✅ **Adapters for agent frameworks** — [`openai_agent.py`](../adapters/openai_agent.py) (official `openai` client) and [`langchain_agent.py`](../adapters/langchain_agent.py), alongside the Node and stdlib-Python entrants. All four pass the identical dry suite. Building them surfaced two real defects: the scripted brain returned a **malformed OpenAI response** (no `id`, `finish_reason`, `object`) that hand-written clients tolerated and real SDKs rejected with a validation error; and the runner's boot budget was **10 s**, while importing LangChain takes ~12 s — the benchmark was silently refusing to start exactly the frameworks it claimed to support. Both fixed; boot budget is now 60 s and tunable with `SUT_BOOT_TIMEOUT_MS`.
  - A framework that insists on **executing the tools itself** (OpenAI Agents SDK, LangGraph's `ToolNode`) cannot be Closed-conformant: the guardrails would stop being identical across entrants. Adapters bind the tool *schemas* and hand the `tool_call` back to the harness. Documented in [ADAPTERS.md](ADAPTERS.md).
- 🔍 **Baselines on the board — under review, not blocked on code.** Seeding reference-GLM, Opus-brain and a couple of public frameworks needs API credit, and it needs a decision first: which brains are worth a published number, at what `k`, and whether a baseline is republished on every dataset version bump or pinned to the version it ran under. Until that's settled, no baseline is authoritative. See [GOVERNANCE.md](GOVERNANCE.md).

### Stage 3 — Public leaderboard & anti-gaming 🏆 (in progress)

*Goal: a board that can't be cheated.* The machinery shipped and is self-testing; what's pending is substance (verified entries), not tooling. Referee's manual: [SUBMISSIONS.md](SUBMISSIONS.md).

- ✅ **Leaderboard generator** — `npm run leaderboard` regenerates [`LEADERBOARD.md`](../LEADERBOARD.md) from `submissions/`: **pass^k headline** (never best-of-k), success, violations, $/conv. **Grouped by (dataset version, digest, split)** — cross-version scores are structurally impossible to mix — and **Closed / Open divisions in separate tables**. Deterministic: the board is a *view* over verifiable artifacts; anyone who distrusts it regenerates it. "Hosted" is GitHub rendering the `.md` — a submission API/queue only earns its complexity when submission volume exists.
- ✅ **Held-out / hidden split** — `--split hidden` + `scenarios-hidden/` (git-ignored, maintainers keep an off-repo backup). The repo commits only a **commitment** ([`scenarios-hidden.sha256`](../scenarios-hidden.sha256): digest + count + seal date, same algorithm as the public digest), proving the set was fixed at a point in time without revealing it — the official score can't have been tuned after seeing submissions. Seeded with 10 scenarios (1 L1 / 6 L2 / 3 L3 · ES 6 / EN 4) mirroring the public taxonomy with fresh personas and two new red-team angles (invoice for a different amount than paid; fake "I already wired the money" confirmation bait). ⚠️ Same caveat as the Stage-1 red-team expansion: linted and dry-run only, **never played against a live judge yet** — ground truth untested until the first maintainer run.
- ✅ **Submission + verification** — a submission IS the report JSON a run emits (manifest + per-run transcripts recorded *during* inference — post-hoc trajectories are structurally impossible), dropped in `submissions/`. `submit:validate` rejects: stripped/empty transcripts, technical errors (the report's own NO CITABLE rule, enforced), digest mismatch, a declared `k` without its runs, malformed results; warns on `k < 8`, judge = brain, missing cost data. `verify:submission` re-runs a **seeded ~20% subset** under the manifest's pinned config and compares per-scenario `pass^k` + violation presence — outcome-level, because buyer and judge carry temperature and token-level equality would be theater. ≥ 80% agreement → **REPRODUCED**; below → the entry is **held and the submitter contacted**. The stamp (`.checked.json`) embeds the report's sha256: swap the file afterwards and the ✓ voids itself.
- ✅ **The whole loop is under test** — `npm run test:stage3` (free, no keys): dry run → validate accepts the honest report → four doped variants rejected → verify reproduces a deterministic run at 100% → an inflated score comes back DIVERGENT → the board lists the entry with its ✓. Building it caught two real harness bugs (the dry assertions crashed on `--solo` subsets; the final report path lied when `--out` was set) — the pattern from Stage 2 repeats: the machinery that checks the bench fixes the bench.
- ✅ **Versioning discipline, made mechanical** — was already policy (digest on every report); now `validate` hard-fails on digest mismatch and the board can't render two digests in one table.
- 🔜 **First verified entries** — the board is honestly empty. Blocked on the same baseline policy as Stage 2's 🔍 (which brains, at what `k`, republish-on-bump or pin), plus API credit. The first real entry should be reference-GLM at `k = 8`, verified with a published seed.

### Stage 4 — Generality & neutrality 🌐 (in progress)

*Goal: bigger than one offer, bigger than one author.*

- ✅ **Domain seam** — `--domain` (default `realestate`, the frozen dataset at the repo root, untouched by Stage 4 — currently v1.1). A domain is `domains/<name>/offer.json` + `scenarios/`, with **its own version and digest**; the judge's price policy, the dry brain's checkout, and the report all derive from the domain's offer (three hardcoded "5000 €" would have silently scored the new domain against real-estate prices). Boards group by (domain, version, digest, split) and **never mix domains**; there is deliberately **no composite score** until ≥ 2 domains have verified entries — averaging a validated domain with a Preview one would launder the weaker number (per-domain breakdown first, composite when it means something; AgentBench's shape, eventually). [DOMAINS.md](DOMAINS.md)
- ✅ **Second domain: `saas` (Preview)** — Kanaly, a fictional WhatsApp-inbox + CRM sold as an annual plan (list 3 000 €, floor 2 700 €), 20 scenarios mirroring the taxonomy (tiers 2/10/8, ES 12/EN 8) incl. 4 domain-specific red-team angles (zero-breach guarantee bait, CEO-authority discount spoof, prompt injection, competitor defamation). ⚠️ Same caveat as every new set: linted + dry-run only, **never played against a live judge** — Preview until validated (lifecycle in [DOMAINS.md](DOMAINS.md)).
- ✅ **Latency as a reported axis** — per-turn agent response time captured during inference (webhook's turn-closing silence is subtracted; it isn't the agent's time), reported as p50/p95 per run and a **p50 column on the board**. SLO *thresholds* are not enforced by the harness: a threshold is a per-round governance parameter ([GOVERNANCE.md](GOVERNANCE.md)) — hardcoding one today would just encode this author's guess.
- ✅ **Governance layer, written down before it's needed** — versioned **submission rounds** (frozen rules per round), **availability tags** (Available / Preview / RDI), **mutual peer-review + spot-audit** with conflict-of-interest rules, and the multi-org steering end-state. Committed design, not live process — it activates when submission volume exists, and the docs say so honestly. [GOVERNANCE.md](GOVERNANCE.md)
- 🔜 **Validate `saas` against a live judge** (discrimination control re-run inside the domain: reference prompt must still beat `bad.md`), then seed its hidden split.
- 🔜 **More languages**, with native-speaker review of personas and rubric — blocked on native speakers, not code.
- 🔜 **Neutral governance, activated** — move decisions to a small multi-org group with conflict-of-interest rules (the MLPerf/MLCommons model). A benchmark controlled by one vendor never becomes *the* referent. Blocked on partner orgs and submission volume; the rules they'd adopt are already frozen above.

### Stage 5 — Reference status 📌 (in progress)

*Goal: the answer to "is this sales agent any good?" is a CloseBench score.*

- ✅ **Public CI** — [`.github/workflows/ci.yml`](../.github/workflows/ci.yml): the 4 dry suites + negotiation dry + the anti-gaming selftest + a release-gate self-check, on every push and PR, zero keys, zero cost. "Never let the dry go red" was a convention in MEMORY.md; now it's a public, mechanical fact — the first rung of [REPRODUCE.md](../REPRODUCE.md)'s auditor ladder is just "look at the Actions tab".
- ✅ **Release gate** — `--min-pass <rate>`: exit 1 unless the run is complete, has **zero violations**, and pass^k ≥ rate. The threshold is the builder's product decision (the benchmark doesn't bless one); the other two conditions are not negotiable — a gate that ignores violations or dead runs is an ornament. Adoption guide with copy-paste CI for agent builders: [ADOPTION.md](ADOPTION.md).
- ✅ **Independent reproduction path** — [REPRODUCE.md](../REPRODUCE.md): the auditor's ladder, cheapest rung first (free harness-honesty check → free paperwork audit of any published claim → paid seeded re-run → what *cannot* be reproduced, stated plainly).
- ✅ **Citability** — [CITATION.cff](../CITATION.cff) (GitHub's "Cite this repository"); a *score* citation must carry domain + version + digest + split, same rule as everywhere else.
- ✅ **Live variant, committed design** — [LIVE.md](LIVE.md): fixed-calendar public refresh per domain (quarterly as working default; `live-YYYY.Q` versions, disjoint from frozen citable versions), retire-into-archive, live-judge validation before seal. Activates with API credit + the first verified entries, and the doc says so instead of promising a cadence it can't keep.
- 🔜 **Third-party audits and independent reproductions** — the tooling above is the invitation; the act is external by definition. First target: one person who isn't the author runs rungs 1–2 of REPRODUCE.md and files an issue with what didn't hold. The filing path is now one click — [`audit-report.yml`](../.github/ISSUE_TEMPLATE/audit-report.yml) asks for the rung, the commit, what happened, **what did not hold up**, and a conflict-of-interest line ([GOVERNANCE.md](GOVERNANCE.md)). Still 🔜, because a template is not an audit.
- 🔜 **Adoption as a release gate; citations in papers and product claims** — external adoption; everything code could contribute (gate flag, CI template, CFF) is shipped.

## How to help move a stage

The fastest contributions right now (Stage 1–3): **human labels** on the judge samples (the κ number gates everything), **new red-team scenarios**, and **the first leaderboard submissions** ([SUBMISSIONS.md](SUBMISSIONS.md)). See [CONTRIBUTING.md](../CONTRIBUTING.md).
